## 二、五条关键设计决策

这些是踩过坑之后定下来的，改动前先读原因。

### 1. 工具叫 `personal_todo`，不叫 `todo_write`
官方标准 preset 自带 `todo_write`（会话任务清单），而**scoped 工具会遮蔽 global 工具**——同名注册后我们的版本对 agent 完全不可见，且不报错。改名后两者并存，工具描述里互相指引。

### 2. 「积压」只针对没有日期的任务
`bucketOf`（`lib/bucket.js`）：
- 有日期 → `today` / `tomorrow` / `week` / **`later`**（本周末之后）
- 没日期 → `stale`（超过 `staleDays`）/ `unplanned`

早期版本把「定了 12 月截止、但创建已久」的任务也算积压，语义是错的——有安排的任务不该叫积压。`later` 是 2026-10-22 实测后补的。

### 3. agent 说完成 ≠ 完成
工具完成写 `doneBy: 'agent'` + `verifiedAt: null`，列表与「已完成」折叠标题上显示「N 待确认」；用户点「确认已完成」才写 `verifiedAt`。用户自己勾选则直接 `doneBy: 'user'` + 立即核实。

### 4. 单 JSON + 原子写 + **可恢复**的串行队列
- 写：`todos.json.tmp` → rename；
- 串行队列防并发丢更新；
- **队尾必须 `catch` 兜住**（`queue = write.catch(() => {})`）：一次 I/O 失败不能让队列永久 rejected，否则本会话后续写入全部静默丢失；
- 写失败置 `writeError` → `list().notices` 带 `write-error` → 客户端常驻警告 + 「重试写入」调 `retryPersist()`。

### 5. 自然语言解析在宿主侧，UI 不调模型
`lib/quickadd.js` 是纯函数（28 个用例）。客户端通过 `POST todo/api/parse` 拿结果，弹窗里用作「一句话填写」。**不要在 UI 里直接调模型**：延迟、失败模式、与"边打字边填"冲突；模型能力走对话 + 工具那条路。

## 三、已知问题与优先级

### 值得一提的三个
1. **`index.js` 与真实 HTTP 传输层没有自动化测试**（172 个测试里 `test/route.test.js` 占 12 个，覆盖 403/405/404、body 解析与 `ready` 生命周期，但用的是 fake `req`/`res`）。chunk 分片、超长 body 等真实传输行为只靠人工验过；要补的话起点是 `test/route.test.js` 已有的 fake-ctx 用法。
2. **非 `io-error` 的写失败没有 UI 反馈**：例如标题超长（>200 字）会 400，客户端只 console，输入保留但没有任何提示。弹窗已有必填校验，长度校验还没有。（v3 已解决：弹窗错误内联 + 长度前置拦截，见 §八）
3. **`later` 不进顶部计数**（页头只显示「今天 N · 积压 N」），也没有分类筛选。（v3 已解决：计数改过滤前全量四项 + 页头筛选，见 §八）

### 最终审查判定「合并后跟进」的（不阻塞）
- store 的多实例文件锁（单进程串行队列已够用）
- 轮询未按页面可见性暂停（隐藏页多耗请求）
- 三份日期键实现（`lib/bucket.js` / `lib/quickadd.js` / `client.js`），行为一致
- `sealed` 复位时机（load 重试与 mutation 的微窗口）
- 循环任务（v2）接入后，这些需要重新过一遍

### v2 实现与计划的两处偏差（都已验证更好）

1. **列表分桶要用「下一个未完成的实例」**：计划给的 `nextOccurrence` 只按规则算下一次，勾掉本周五后仍返回本周五，行不会滚到下周。实现改成先跳过 `completions` 里已有的日期（`nextOpenOccurrence`），这才符合"勾掉这次、滚到下次"的产品语义。
2. **`complete` 的 `date` 必须一路透传到 store**：计划只要求 `api.js` 加 `occurrences`，但工具/接口的 `date` 若不透传，日历里勾某一天会变成勾今天。

## 五、怎么开发、怎么验证

```bash
cd D:\dsh-sidebar-todo

node --check client.js      # 客户端没有构建步骤，只做语法检查
```

**装/更新插件**
- 首次：`plugin_manager` 的 `install_bundle`，`target: D:\dsh-sidebar-todo`
- 改 `index.js` 之后：必须 `set_plugin` 对 `include:dsh-todolist` 先 `false` 再 `true` 才会重新加载模块（`install_bundle` 只会回 `already-installed`）
- 改 `client.js` 之后：宿主的 HMR 会轮询 bundle 的 mtime，几百毫秒内生效；不确定就刷新页面

**客户端验证的现实**
没有浏览器测试框架。能做的是：`node --check`、`test/client-tokens.test.js`（扫描 `var(--dsw-*)` 是否都在宿主的 403 个真实 token 里）、以及仓库外的 DOM-less 冒烟（stub React + fetch 驱动真实 `client.js`，历次任务都这么验，脚本没入库）。**最终仍然要靠人眼看**。

### DSH 升级对本插件的影响

本插件**不 import 任何 `@deepseek-ai/*` 包**（`dependencies` 与 `peerDependencies` 都为空），只依赖宿主在运行时提供的几样东西。按风险排序：

| 依赖项 | 用在哪 | 升级风险 | 坏了会怎样 |
|---|---|---|---|
| `window.__ModuleLoader__.load({ id, factory })` | `client.js` 整份 | **高**——这是客户端产物格式，改了插件直接不加载 | 侧栏没有「待办」，控制台报模块错误 |
| `ctx.slots.inject / register` + 槽位名 `sidebar.panellist` / `main` | 入口行与面板 | **中**——槽位选项（`label` / `locale` / `inject`）或语义变化 | 入口消失或点了不切换 |
| `ctx.webServer.register({ kind: 'prefix' })` + `ctx.connection.requestRejection(req)` | `index.js` 路由 | **中**——服务名或签名变化 | 面板一直显示「读取失败」 |
| `ctx.tools.register` 的 `ToolDefinition`（`parameters` / `output.schema` / `output.render`） | `lib/tool.js` | **中**——字段形状变化 | agent 侧看不见工具或返回渲染异常 |
| `ctx.locale.register / bind`、`ctx.get('locale')` | 文案 | 低 | 退化成只有中文（有 `dict.zh` 兜底） |
| `--dsw-alias-*` 等主题 token | 全部样式 | 低 | 视觉降级（漏出默认色），不会崩 |
| `dsh.bundle.patch` / `dsh.client.inject` 清单字段 | `package.json` | 低-中 | 装不上或客户端半不激活 |
| 数据文件 `todos.json` | `lib/store.js` | **无**——格式是我们自己的 | — |

**升级后的自查顺序**（5 分钟）：

1. `git -C D:\dsh-sidebar-todo log --oneline -1` 记下当前插件版本；
2. 重载插件（`set_plugin` 关再开）；
3. 刷新页面：侧栏有没有「待办」→ 点开有没有列表 → 能不能新建一条；
4. 让 agent 调 `personal_todo list`，确认工具还在、返回正常；
5. `node --test`（172 个）——**只覆盖 `lib/`，宿主接口坏了它测不出来**，所以第 3、4 步不能省。

若第 1 或第 3 步失败，最常见的是 `__ModuleLoader__` 或槽位 API 变了，需要按新版宿主的模板改 `client.js`，而不是改数据。

**版本钉子**：插件本身不锁宿主版本（`package.json` 无 `engines`）。如果将来发现某个宿主大版本会破坏兼容，在 README 里补一段"已知兼容版本"，并像 `dsh-better-sidebar` 那样把支持线写清楚——它的 README 就维护了一张宿主版本 ↔ 插件版本对照表，可直接照抄这个做法。

## 六、踩过的坑（改这块代码前值得知道）

1. **`store.load()` 的 rejection 会杀掉宿主进程。** 插件激活时没人 await 它，Node 24 下 unhandledRejection 直接退出。修法是另挂 `void ready.catch(() => {})`，原 promise 仍给调用方 await。
2. **写盘队列一次失败就永久中毒。** `queue = queue.then(...)` 后任一环 reject，后续 `.then` 全部跳过，写入静默丢失。队尾必须 catch。
3. **解析器会吞字。** 两个形态都出现过：先摘再校验（`31/10` 被摘掉又判非法）、以及多个候选正则全部无条件 `take`（`下周三吃饭下周五请假` 把「周五」也啃掉）。原则：**没被采用的片段必须留在标题里**。
4. **并发子代理会互相污染 git index。** 并行跑任务时一律 `git add <显式路径>`，禁止 `git add -A`；共享文件（`client.js`、`index.js`）的任务必须串行。
5. **`node --test test/` 在 Node 24 上会解析失败**，用裸 `node --test`。
