## 三、D 层：六条用户旅程

| # | 旅程 | 断言要点 |
|---|---|---|
| D1 | 每周五的日报 | 周内可见（`dueDate` 是本周五）→ 完成 → 整行消失 → 日历仍有且 `done:true` → 撤销 → 回列表 |
| D2 | 每天的日报 | 今天出现；完成今天后消失；`occurrences` 当天 `done:true` |
| D3 | 每月 31 号 | 2 月不出现；3 月 31 日出现（跨月规则） |
| D4 | 分类改名与删除 | 改名合并到目标分类；删除后退回 `null`，`categories()` 为空 |
| D5 | 写失败与恢复 | 写失败 → `notices` 含 `write-error` → `retryPersist()` → 落盘且通知消失 |
| D6 | v1 老数据 | 缺 `repeat` / `completions` / `doneBy` 时 `list()` 正常 |

### 已知限制

- D1 的 `bucket` 断言按运行日推导（周一–周五为 `week`/`today`，周末为 `overdue`），不是写死值。
- C 层用 fake `req`/`res` 直接驱动 handler，**不覆盖真实 Node HTTP 传输层**（chunk 分片、超长 body）。
- 没有真实浏览器 E2E；`client.js` 的行为只由 DOM-less 冒烟（stub React，脚本不入库）与人工验证覆盖。
